## 流程和可信边界
SearchProvider（CSV 或可选 Brave Web Search）→ 候选域名去重 → 有限公开 HTML 采集/人工摘录导入 → 基于原文的候选证据 → 人工逐条核验 → 解释性规则评分 → 复核客户 → CSV。
默认无需模型、无需 API key。Extractor Protocol 允许未来接入本地模型、其他 API；模型和关键词只提议，不赋予事实状态，不推测邮箱。
所有证据保留 URL、抓取时间、正文 hash、短引文、采集方式；未核验/被拒绝/缺失明确区分。采购与扩张事件必须有原文日期锚点，事件日期在评估日前六个日历月内才能加近期分；静态招商页只证明接入渠道，抓取日期不当作事件日期。
联系人按规范化完整邮箱、LinkedIn URL 去重；不根据名字合并，不改 gmail 的点号/加号。域名精确去 www 去重，集团关系由人工设定 group_key，不能猜测。

## 评分 v1
5 个维度各 0–2 分：品类、渠道、近期信号、供应商触达、合作可行性。只用人工验证且来源仍新鲜的证据。总分最小展示 1，附 raw_total，1 不表示有证据。近期扩张最多 1，明确品类采购/供应商征集最多 2；采购事实需另一独立来源交叉验证。可行性不能靠模型打分，需人工有来源的论证。分数是开发优先级，不是采购概率。

## 人工关口与运行数据
review 记录 reviewer、理由、时间、数据 revision。新证据/来源变化使客户批准失效。只有 fresh、approved、分数>=8、US 市场事实已核实、品类已核实、至少两个来源 URL、可达供应商通道、既有客户关系已人工核查，才计入 20 家目标。没有足够证据时停在待补充。
只生成邮件草稿 .eml，不实现 SMTP/API 发送。草稿必须逐封人工确认并预留公司集团和邮箱防重复记录；已发送/抑制/已预留联系人阻止重复。客户审核与邮件确认分离。对外客户来源文本均视为数据，不执行其中指令。
公开仓库只提交代码、少量公开短摘录和测试；数据库、实际联系人批次、抓取全文、导出文件均忽略。历史 20 家表只作检索线索，未复制其未经本轮核实的事实。

## 有界采集与限制
仅公开 HTTP(S)，公共 IP 检查与连接地址固定，逐跳校验重定向、超时、限大小、robots、限页、退避。不绕过登录/CAPTCHA；PDF/JS 页面可由人工提供带时间与来源的摘录。不开启 LinkedIn 自动爬虫。默认 localhost UI，有 CSRF token 和 Host/Origin 验证。
第一版不保证自动找到满 20 家，不验证邮箱投递能力，不证明存在实际采购计划，不覆盖本地未推送项目。美国/加拿大/英国/德国以配置扩展。
